## Summary

Feature is implemented end-to-end under the `awaiting-replies` / `AwaitingReply` domain. Backend stores open per-employee rows (`apps.channels.models.AwaitingReply`), creates/resolves them from channel message and reaction Celery hooks, and exposes list + dismiss on the internal workspace API. Frontend mounts `AwaitingRepliesWidget` on the personal dashboard notifications tab, loads via Redux `store/awaiting-replies`, and opens the entity with `messageUuid` context. UI copy uses i18n keys `AwaitingMyReply*` (title/empty/dismiss), not hardcoded Russian strings in `src/`.
