## Summary

Флаг хранится на контакте (`Contact.has_missed_call`), выставляется/сбрасывается сервисом `MissedCallService` при обработке сообщений чата (телефония `call_missed` / исходящий ответ оператора). На фронте иконка `phone-call-01` (`MissedCallIndicator`) показывается на Kanban-карточке лида и в detail chat panel по `hasMissedCall` из HTTP и live-override из WS `contactFlags`. После первого исходящего сообщения Upservice (или online-chat / private comment с источником `upservice`) флаг на контакте сбрасывается → lead `entity-updated` с полным снимком `contact_flags` → индикатор исчезает.

## API alignment

- In `catalog/api.md` нет публичных CRM/missed-call ресурсов (`entities: none` в requirement) — `- none` для public catalog paths.
- Internal contract useful for Playwright mocks (camelCase as consumed by FE after transform; snake_case on BE):
  - **HTTP contact / lead `taskInfo.contacts[]`:** `hasMissedCall: boolean` (`has_missed_call` on BE via `ContactSerializer` / `ContactTaskInfoSerializer`).
  - **WS `entity-updated` for lead:** `updatedFields.contactFlags: Array<{ contactId: number, hasMissedCall: boolean }>` (`updated_fields.contact_flags` / `contact_id` / `has_missed_call` on BE). Full ordered snapshot of linked contacts replaces prior live flags for that lead.
  - Flag is **per contact**, not per lead; Kanban shows indicator if **any** linked contact has the flag (`getLeadHasMissedCall`).
  - Clear path for AC «первое исходящее сообщение Upservice»: chat message/comment with source `upservice` (also `online-chat`) → `MissedCallService.process_message` → `has_missed_call=False` → lead `entity-updated` with `contact_flags` all false for that contact → FE hide chip. Multiple missed calls are a single boolean; one clear removes the indicator for that contact.
