## Summary

Виджет **«План на текущую неделю»** реализован целиком на клиенте как `WeekPlanWidget` на личном дашборде (`NotificationsView`). Отдельного backend-эндпоинта виджета нет: данные собираются параллельно из существующих list API — задачи/тикеты/лиды через `fetchTasksLocal` → `GET /v1/{workspace}/tasks/` с `my_tasks` + `date_end_gte/lte` и активными статусами; записи справочников через `apiV1.assets.fetch` → `GET /v1/{workspace}/assets/` с `responsible` + `date_end_*`; лиды дополнительно фильтруются по «активным» статусам CRM-пайплайнов. Неделя — ISO (пн–вс) через `dayjs().startOf/endOf('isoWeek')`; UI группирует по дням, Virtuoso-список, аккордеон в localStorage.

## API alignment

- Catalog `GET /v1/tasks` aligns with widget task/ticket/lead loads (`my_tasks`, `date_end_gte`/`date_end_lte`, `kind`, `status`); handlers: `TaskFilterSet` + `TaskViewSet`.
- Catalog lists `GET /v1/directory-records` for directories; runtime client uses internal **`/v1/{workspace}/assets/`** (AssetFilterSet) for «записи справочника» — not a separate week-plan resource.
- No catalog entry for dashboard/week-plan widget or dedicated leads list; leads reuse tasks API (`kind=lead`) plus CRM pipeline fetches for status filtering.
- `GET /v1/employees` not used by this widget path (employee id from workspace store).

## Gaps

- Timezone: week bounds use client `dayjs` local time; not traced against server employee timezone settings.
- Asset «active» status filtering: assets query only `responsible` + `dateEndRange` — no explicit completed/cancelled exclude found in widget params.
- Catalog public `directory-records` vs client `assets` naming not fully mapped in this pass.
- Backend search was filter/viewset-level only (no new widget-specific services).
