На личном Web-дашборде появляется виджет «Ждут моего ответа»: список сообщений, по которым от текущего сотрудника ожидается ответ (персональный `@mention`, `@mention` подразделения, в котором он состоит, Reply на его сообщение, новое сообщение в беседе 1:1, входящее от клиента в контакте или незакрытом лиде, где он ответственный). Источники — задачи, тикеты, лиды, контакты, записи справочников и беседы; сообщения обычных сотрудников и ИИ-сотрудников учитываются одинаково. Для входящего клиента в **чат контакта** бейдж строки виджета у ответственного сотрудника выбирается по исключающему приоритету **Ticket > Lead > Contact** (активный тикет перекрывает лид и контакт; при отсутствии тикета активный лид перекрывает контакт). Состояние не снимается прочтением или открытием сущности; снимается ответом в той же сущности или беседе, emoji-реакцией на сообщение, создавшее ожидание, или действием «Ответ не требуется». Клик по элементу открывает сущность или беседу в контексте сообщения. Кнопка «Посмотреть все» открывает модальное окно со списком, мультифильтром по типам сущностей и скроллом при большом числе элементов; несколько сообщений по одной сущности и id группируются.

## Testable

- Открыть личный дашборд Web под текущим сотрудником → отображается виджет с заголовком «Ждут моего ответа»
- При отсутствии сообщений, ожидающих ответа текущего пользователя, открыть личный дашборд → виджет показывает пустое состояние «Сейчас никто не ждёт вашего ответа»
- Пользователь A упомянут персонально через `@mention` в чате задачи; пользователь B не упомянут; оба открывают личный дашборд → сообщение есть в виджете A и отсутствует в виджете B
- Пользователь состоит в подразделении, которое упомянули через `@mention` в сообщении → сообщение появляется в виджете этого пользователя
- На сообщение текущего пользователя сделан Reply (в том числе в записи справочника) → Reply появляется в виджете текущего пользователя
- В беседе 1:1 с текущим пользователем приходит новое сообщение без `@mention` → сообщение появляется в виджете
- Текущий пользователь — ответственный за контакт; клиент отправляет входящее без `@mention` и без Reply → сообщение появляется в виджете ответственного
- Текущий пользователь — ответственный за лид; клиент отправляет входящее без `@mention` и без Reply → сообщение появляется в виджете ответственного
- Текущий пользователь не ответственный за контакт или лид; клиент отправляет обычное сообщение без персонального `@mention` и без Reply на сообщение этого пользователя → сообщение не появляется в его виджете
- Текущий пользователь не ответственный за контакт или лид; его персонально упомянули через `@mention` в этой сущности → сообщение появляется в его виджете
- Текущий пользователь не ответственный за контакт или лид; на его сообщение в этой сущности сделали Reply → Reply появляется в его виджете
- Клиент пишет во входящий чат контакта; у контакта нет активного тикета и нет активного лида; открыть виджет ответственного → бейдж Contact / элемент относится к контакту
- Клиент пишет во входящий чат контакта; есть активный тикет (активного лида нет); открыть виджет ответственного → бейдж Ticket
- Клиент пишет во входящий чат контакта; активного тикета нет, есть активный лид; открыть виджет ответственного → бейдж Lead
- Клиент пишет во входящий чат контакта; одновременно есть активный тикет и активный лид; открыть виджет ответственного → бейдж Ticket (не Lead и не Contact)
- У контакта несколько активных лидов с одним и тем же ответственным (контакт и лиды); клиент пишет внешнее сообщение в чат контакта → в виджете этого ответственного появляются отдельные элементы по каждому такому лиду
- Ответственный за контакт и ответственные за связанные активные лиды разные; клиент пишет внешнее сообщение в чат контакта → элемент появляется у ответственного за контакт
- Ответственный за контакт и ответственные за связанные активные лиды разные; клиент пишет внешнее сообщение в чат контакта → элемент появляется у ответственного за каждый такой лид
- Один активный лид на контакт и у контакта с лидом один и тот же ответственный; клиент пишет внешнее сообщение в чат контакта → в виджете появляется один элемент, относящийся к лиду
- ИИ-сотрудник персонально упомянул текущего пользователя через `@mention` → сообщение появляется в виджете
- ИИ-сотрудник упомянул подразделение, в котором состоит текущий пользователь → сообщение появляется в виджете
- ИИ-сотрудник сделал Reply на сообщение текущего пользователя → Reply появляется в виджете
- ИИ-сотрудник отправил сообщение в беседе 1:1 с текущим пользователем → сообщение появляется в виджете
- ИИ-сотрудник отправил в сущности обычное сообщение без персонального `@mention` и без Reply на сообщение текущего пользователя (пользователь не в сценарии «ответственный за контакт/лид с входящим клиента») → сообщение не появляется в виджете
- Сообщение уже в виджете; пользователь только открывает сущность, просматривает или отмечает сообщение прочитанным, не отвечая и не ставя реакцию → сообщение остаётся в виджете
- Пользователь отправляет сообщение в той же сущности или беседе, откуда элемент в виджете → этот элемент перестаёт отображаться
- Пользователь ставит emoji-реакцию на сообщение, создавшее ожидание → элемент перестаёт отображаться в виджете
- Для элемента в виджете выбрать действие «Ответ не требуется» → элемент перестаёт отображаться
- Для сообщения ИИ-сотрудника в виджете ответить в сущности/беседе → элемент перестаёт отображаться
- Для сообщения ИИ-сотрудника в виджете поставить emoji-реакцию на это сообщение → элемент перестаёт отображаться
- Для сообщения ИИ-сотрудника в виджете выбрать «Ответ не требуется» → элемент перестаёт отображаться
- Нажать на элемент виджета → открывается соответствующая сущность или беседа в контексте этого сообщения
- В виджете есть элемент из задачи (по правилам ожидания ответа) → элемент задачи отображается в виджете
- В виджете есть элемент из тикета (по правилам ожидания ответа) → элемент тикета отображается в виджете
- В виджете есть элемент из лида (по правилам ожидания ответа) → элемент лида отображается в виджете
- В виджете есть элемент из контакта (по правилам ожидания ответа) → элемент контакта отображается в виджете
- В виджете есть элемент из записи справочника (по правилам ожидания ответа) → элемент записи справочника отображается в виджете
- В виджете есть элемент из беседы (по правилам ожидания ответа) → элемент беседы отображается в виджете
- Нажать «Посмотреть все» в виджете → открывается модальное окно со списком ожидающих ответа
- В модальном окне «Посмотреть все» → доступен мультифильтр по типам сущностей с возможностью множественного выбора
- В модальном окне «Посмотреть все» при большом числе элементов → появляется скролл списка
- В одной сущности с конкретным id пришло больше одного сообщения, ожидающего ответа → в виджете элементы группируются по этой сущности и id
