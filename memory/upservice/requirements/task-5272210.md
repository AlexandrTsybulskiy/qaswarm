Пользователь настраивает **правило автоматизации** для лида CRM: при **изменении стадии лида** (включая создание лида сразу на стадии) в заданной **воронке** и на заданной **стадии** система планирует **разовое отложенное сообщение** в чат связанного **контакта** с настраиваемым текстом и задержкой. Отправитель — **ответственный по лиду** на момент срабатывания; канал выбирается по правилам единственного доступного исходящего канала или последней коммуникации. Поведение отображения и доставки совпадает с ручным отложенным сообщением контакту (story 4985393).

## Testable

- Пользователь открывает «Правила автоматизации» в настройках workspace → в типе сущности доступен **Лид**
- Пользователь выбирает триггер **Изменение стадии лида** → в условиях доступны поля **Воронка** и **Стадия воронки**
- Пользователь выбирает триггер **Изменение стадии лида** → в действиях доступно **Отложенное сообщение в чат контакта**
- Пользователь выбирает действие **Отложенное сообщение в чат контакта** → доступны поля **текст сообщения**, **задержка в днях** и **задержка в часах**
- Активное правило: тип **Лид**, триггер **Изменение стадии лида**, условия воронка **A** и стадия **X**, действие текст **T**, задержка **2 часа**; у контакта лида один канал с исходящими → лид переводят на стадию **X** в воронке **A** → через **2 часа** отложенное сообщение **T** отправляется в чат контакта
- Активное правило с задержкой **2 часа**; у контакта лида один канал с исходящими → лид переводят на целевую стадию → отложенное сообщение отправляется **от имени ответственного по лиду** на момент срабатывания
- Активное правило с задержкой; у контакта лида несколько каналов с исходящими, последняя переписка в **WhatsApp** → лид переводят на целевую стадию → отложенное сообщение планируется в чат контакта по каналу **WhatsApp**
- Активное правило с задержкой **2 часа** → лид переводят на целевую стадию → по истечении задержки отправленное сообщение **видно в чате контакта**
- Активное правило с задержкой **2 часа** → лид переводят на целевую стадию → по истечении задержки отправленное сообщение **видно в диалоге лида**
- Активное правило с задержкой; ответственный по лиду **не имеет** прав на исходящее сообщение контакту по каналу действия → лид переводят на целевую стадию → отложенное сообщение **не создаётся**
- Отложенное сообщение запланировано правилом → лид переводят на другую стадию до истечения задержки → запланированное сообщение **не отменяется**
- Отложенное сообщение запланировано правилом → администратор **выключает** правило до истечения задержки → запланированное сообщение **не отменяется**
- Активное правило с задержкой; отложенное сообщение уже запланировано → администратор **выключает** правило → **новые** отложенные сообщения этим правилом **не планируются**
- Правило с условием воронка **A**, стадия **X** активно → лид уходит со стадии **X** и снова переходит на стадию **X** в воронке **A** → планируется **новое** отложенное сообщение по **актуальным** настройкам правила
- Активное правило с текстом **T1** и задержкой **2 часа**; отложенное сообщение запланировано → администратор меняет текст на **T2** и задержку на **1 час** → лид **снова** переходит на целевую стадию → планируется сообщение с текстом **T2** и задержкой **1 час**
- Лиды уже находятся на стадии **X** в воронке **A** → администратор **создаёт и включает** правило для воронки **A** и стадии **X** с задержкой → лиды **не переводят** на другую стадию → отложенные сообщения для этих лидов **не планируются**
- Правило с условием воронка **A**, стадия **X** активно → лид **создаётся** сразу на стадии **X** в воронке **A** → отложенное сообщение **планируется**
- Пользователь с правами управления правилами автоматизации в workspace → открывает настройки workspace → раздел **Правила автоматизации** **доступен**

## Gaps

- В `entities/` и `catalog/api.md` нет карточек CRM, лидов, воронок, контактов и правил автоматизации; проверка UI-only / API-unknown.
- Макет Figma по ссылке из задачи недоступен (403); детали UI полей задержки и валидации минимума **1 минута** не подтверждены дизайном.
- Не описана проверка логики «И» при нескольких дополнительных условиях кроме воронки и стадии.
- Не описано поведение при нескольких контактах, связанных с одним лидом.
- Не описано явное подтверждение повторяемости «Никогда» в UI действия.
- Не описано поведение для пользователя **без** прав управления правилами автоматизации (кроме доступности раздела).
- Детали паритета с ручным отложенным сообщением (story 4985393) не разобраны в этой задаче.
