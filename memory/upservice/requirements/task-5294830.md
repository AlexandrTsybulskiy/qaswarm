Система рассчитывает и обновляет компонент **балл активности** в едином скоринге лида по фиксированным правилам на основе продуктовых событий workspace компании лида. Балл = сумма сработавших критериев (макс. **75**): приглашение сотрудника (+25), ≥1 действие в продукте (+10), ≥5 суммарных действий (+15), возврат после 24 ч с первого входа (+25). Учитываются только события из каталога: `add_task`, `edit_task`, `finish_task`, `add_meeting_task_in_calendar`, `add_project`, `add_asset`, `add_deal`, `add_contact`, `add_ticket`, `finish_ticket`, `create_channel`, `discussion_created`, `colleague_invitation`. Все лиды одной компании с одним workspace имеют одинаковый балл активности. Пересчёт при каждом новом событии из каталога (критерии 3–5) и при каждом новом входе пользователя workspace (критерий 6). Не входит: отображение балла в CRM, отчёты, настраиваемые правила, tier/decay/отрицательные баллы, другие компоненты единого скоринга.

## Testable

- Лид в едином скоринге; в workspace выполнены 3 события `add_task`, приглашений не было, возврат после 24 ч не зафиксирован → балл активности = **10** (критерий «≥ 1 действие»)
- Лид в едином скоринге; выполнено одно событие `add_contact`; первый вход в workspace — 1 марта 10:00, второй вход любого пользователя — 2 марта 11:00 → балл активности = **35** (10 + 25 за возврат)
- Лид в едином скоринге; выполнены `colleague_invitation`, `add_task`, `add_task`, `edit_task`, `finish_task`, `add_project`; возврат не зафиксирован → балл активности = **50** (25 + 10 + 15; шесть фактических событий из каталога)
- Два лида одной компании и одного workspace; в workspace выполнено 2 события `add_task` → у обоих лидов одинаковый балл активности = **10**
- В workspace зафиксировано событие `colleague_invitation` (один раз) → к баллу активности добавляется **+25** (однократно; повторные приглашения не увеличивают этот критерий)
- В workspace зафиксировано ≥ 1 событие из каталога (без приглашения) → к баллу активности добавляется **+10** (однократно; дополнительные события до порога 5 не добавляют второй +10)
- В workspace накоплено 4 фактических события из каталога (без приглашения и возврата) → балл активности = **10** (только критерий «≥ 1 действие»; критерий «≥ 5 действий» ещё не сработал)
- В workspace накоплено 5-е фактическое событие из каталога → к баллу активности добавляется **+15** за критерий «≥ 5 действий» (однократно)
- Повторные однотипные события из каталога (например три `add_task`) → каждое учитывается как +1 к суммарному счётчику для критерия «≥ 5 действий»
- Событие `colleague_invitation` → учитывается в суммарном счётчике фактических событий для критерия «≥ 5 действий» (как в примере 3)
- Первый фактический вход любого пользователя workspace после регистрации workspace; второй вход любого пользователя не ранее чем через 24 ч после первого → к баллу активности добавляется **+25** за возврат (однократно)
- Первый вход в workspace; повторный вход любого пользователя менее чем через 24 ч после первого → **+25** за возврат не начисляется
- В workspace сработали все четыре критерия (приглашение, ≥1 действие, ≥5 действий, возврат после 24 ч) → балл активности = **75** (максимум; сверх лимита не растёт)
- После нового события из каталога в workspace → пересчитываются критерии приглашения, «≥ 1 действие», «≥ 5 действий» и итоговый балл активности для лидов этой компании/workspace
- После нового входа пользователя workspace → проверяется критерий возврата после 24 ч и при необходимости пересчитывается балл активности
- События только из перечисленного каталога участвуют в расчёте; событие вне каталога → не увеличивает счётчик действий и не меняет балл активности
- Лиды одной компании с разными workspace → баллы активности могут различаться (балл привязан к workspace, не к компании глобально)
- Выполнено одно событие `add_project` в workspace без других событий каталога → балл активности = **10**
