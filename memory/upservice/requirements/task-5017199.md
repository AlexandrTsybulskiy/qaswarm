Пользователь запрашивает у AI-сотрудника, в каком файле хранится указанная информация. AI выполняет семантический поиск по разделу «Мой диск» текущего воркспейса (название и содержимое), учитывает права на просмотр, возвращает релевантные файлы вложением. Новые и изменённые файлы попадают в выдачу после фоновой индексации. При отсутствии совпадений, сбое поиска, повреждённом файле или неясном контексте AI сообщает об этом и не обрабатывает содержимое без доступа.

## Testable

- Пользователь просит AI-сотрудника найти файл по смыслу запроса в рамках текущего воркспейса → запрос уходит на сервер, сервер обращается к поисковому сервису и возвращает релевантные файлы из «Мой диск» с учётом прав доступа.
- В доступных файлах совпадает название с запросом → файл входит в выдачу.
- В доступных файлах совпадает содержимое (текст), а не только название → файл входит в выдачу.
- Файл есть в воркспейсе, но у AI-сотрудника нет права на просмотр → файл не попадает в выдачу и его содержимое не раскрывается.
- Поиск находит файлы → ответ содержит прикреплённый файл(-ы), отсортированные по релевантности.
- В доступных файлах нет запрашиваемой информации → AI сообщает об этом пользователю и не прикладывает нерелевантные файлы как найденные.
- При поиске ошибка (повреждённый файл, сбой поискового сервиса) или неясен контекст запроса → AI сообщает об этом пользователю и не начинает обработку содержимого до получения доступа к файлам.
- Файл только что загружен или изменён, индексация ещё не завершена → файл может отсутствовать в выдаче до фоновой индексации.
- Кейс 1: «Пришли мне файл, в котором расписан регламент работы AI-сотрудника» → AI ищет по названию и тексту доступных документов и выдаёт соответствующие файлы вложением.
- Кейс 2: «В каком документе хранятся инструкции по работе с базой знаний?» → AI ищет по названию и тексту доступных документов и выдаёт соответствующие файлы.
- Кейс 3 (первый запрос): «У нас где-то лежит файл, в котором описан регламент работы AI-сотрудника.» → AI ищет по названиям и контексту доступных файлов и выдаёт соответствующие файлы.
- Кейс 3 (второй запрос): после выдачи файла пользователь спрашивает «что из себя представляет этот регламент?» → AI просматривает доступные файлы из контекста и отвечает по содержимому.

## Gaps

- В снимке задачи нет Figma-URL → `source_design: none`, `figma_urls: none`; UI чата с AI, формат вложений и раздел «Мой диск» не сверять с макетом.
- В `catalog/api.md` нет ресурса семантического поиска по файлам, AI-сотрудника и «Мой диск». Публичные пути по файлам: `POST /v1/files/`, `GET /v1/files/{file_id}/url`; связанные: `GET /v1/tasks/{task_id}/attachments`, поле `file_list` у задач, `GET|POST /v1/channels/messages`. Эндпоинты поискового сервиса, индексации и прав файла не выдумывать.
- `entities/files.md` — `map` only: upload и URL скачивания; полей «Мой диск», прав на просмотр, автора, типа, даты добавления, срока актуальности, связей с задачами/справочниками в карточке нет.
- Критерий 4 («по возможности»): сочетание поиска с фильтрами (тип связи с задачами/справочниками, автор, теги, тип, дата добавления, срок актуальности) не обязателен; точная семантика фильтров и UI не зафиксированы. `entities/tags.md` и `entities/directories.md` — `map` only.
- Не зафиксированы: порог релевантности, лимит числа вложений, язык запроса, что считать «непонятным контекстом», шаблон сообщений об ошибке/пустой выдаче, SLA индексации.
- `entities/employees.md` и `entities/channels.md` — `map` only: идентификация AI-сотрудника, его ACL на файлы и канал диалога с пользователем не детализированы.
