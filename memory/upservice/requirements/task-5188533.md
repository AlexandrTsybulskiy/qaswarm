В ленте уведомлений (колокольчик) записи по лидам должны корректно идентифицировать сущность как лид: шапка по шаблону `ID {id лида} {название лида}` со ссылкой на карточку лида; в тексте — формулировки про «лид», а не «задача»; ссылка из ленты ведёт на лид (для нотификаций о сообщениях в чате — на чат с контактом, как сейчас). По лидам доставляются только нотификации из CRM-перечня (в т.ч. типы 103 и 105 по сроку «выполнить по»: наступление и приближение); нотификации, есть у задач, но не у лидов, при работе с лидом не приходят. В ленту попадают те lead-нотификации, у которых в таблице CRM по колонке ленты не стоит «-».

## Testable

- Наступает срок «выполнить по» у лида → пользователю приходит нотификация по лиду одного из типов id 103 или 105 (пара типов для наступления и приближения срока; оба типа описаны в CRM-разделе файла нотификаций).
- Срок «выполнить по» у лида приближается → пользователю приходит вторая из пары нотификаций id 103 / 105 по правилам CRM (приближение срока).
- Пользователь выполняет действие по лиду, для которого в CRM-файле нотификаций (раздел CRM) задана нотификация → приходит только соответствующая lead-нотификация из этого перечня.
- Пользователь выполняет по лиду действие, для которого нотификация есть у задач, но в CRM-перечне для лидов отсутствует → нотификация по этому действию не приходит.
- Приходит lead-нотификация, у которой в CRM-таблице по записи в ленте не стоит «-» → в ленте уведомлений появляется запись об этой нотификации.
- В ленте открыта запись по лиду (не про сообщения в чате) → шапка отображается как `ID {id лида} {название лида}` и является ссылкой на карточку этого лида.
- Клик по ссылке из записи ленты по лиду (не про сообщения в чате) → открывается сущность лида, а не задача.
- В тексте записи ленты по лиду → используется формулировка «лид», а не «задача».
- В тексте нотификации после упоминания лида → отображается `ID {id} {название}` лида, а не только числовой id.
- Приходит нотификация о сообщениях в чате по контексту лида → ссылка из ленты ведёт на чат с контактом (как для текущих chat-нотификаций), а не подменяется ссылкой на задачу.

## Gaps

- В снимке задачи нет Figma-URL → `source_design: none`, `figma_urls: none`; UI ленты и шаблоны не сверять с макетом.
- Полный перечень разрешённых lead-нотификаций задан внешним Google Doc (`docs.google.com/document/d/1uTg45rIFwQPxf-IELTmchSjZoHwHAlk8`); содержимое документа в снимке задачи отсутствует — кроме явно названных id 103 и 105 и правила «только CRM, без task-only» полный allow/deny-список из памяти не восстанавливать.
- Какой из id 103 / 105 соответствует «наступлению» vs «приближению» срока «выполнить по», порог «приближается» и точные тексты шаблонов этих двух типов в тикете не зафиксированы — проверять пару типов и оба триггера без выдуманного маппинга id↔событие.
- Смысл колонки «запись в ленте» со значением «-» и полный набор строк CRM-таблицы в снимке не приведены — критерий «не стоит -» проверять по актуальной CRM-таблице в продукте/доке, не выдумывать строки.
- В `catalog/api.md` нет ресурсов CRM / leads / notifications / feed. Публичный каталог: files, channels, employees, projects, sprints, tags, tasks, directories. Эндпоинты ленты и доставки нотификаций не выдумывать; проверка UI-only / API-unknown.
- В `entities/` нет карточек лидов и уведомлений; `entities/tasks.md` — задачи Upservice (`kind` task/meeting/ticket и т.д.), не CRM-лид. `entities: none`. Не привязывать lead-нотификации к API задач как к целевой сущности перехода из ленты.
