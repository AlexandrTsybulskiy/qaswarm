На карточке лида рядом с этапом воронки появляется отдельное поле стадии жизненного цикла со справочником Visitor, Lead, MQL, SQL, Opportunity, Won; поля независимы, новый и существующие лиды при первом включении получают Lead. Критерий 4 не актуален: переходы следуют критерию 2 — только последовательная цепочка без пропусков; из Won можно перевести в любую другую стадию. Менять стадию могут только ответственный за лид и его руководитель (линейный/орг-руководитель ответственного); остальные, включая автора лида, если он не ответственный и не этот руководитель, видят стадию только для просмотра. Переходы только ручные; в историю пишутся предыдущая и новая стадии, сотрудник и дата/время, отдельные периоды и дата первого достижения. Статус компании, lifecycle контакта, pre-lead Visitor до карточки, workflow/scoring и агрегаты времени на стадии — вне этой story.

## Testable

- Открыть карточку лида → отдельно показаны два независимых поля: «этап воронки» и «стадия жизненного цикла».
- Открыть поле «стадия жизненного цикла» → доступны значения справочника: Visitor, Lead, MQL, SQL, Opportunity, Won.
- Создать новый лид → стадия жизненного цикла по умолчанию Lead.
- На существующей карточке лида открыть поле стадии → Visitor есть среди значений справочника (ручная установка на уже созданной карточке; pre-lead Visitor до появления карточки — вне скоупа).
- Как ответственный за лид со стадией Lead сменить стадию на соседнюю MQL → стадия на карточке = MQL (смежный шаг вперёд по критерию 2).
- Как ответственный сменить стадию Opportunity → Won → стадия = Won.
- Со стадии Lead попытаться перейти на Opportunity (пропуск MQL и SQL) → изменение не сохраняется; стадия остаётся Lead (критерий 2: только последовательные переходы, перепрыгивать нельзя).
- Со стадии SQL попытаться перейти на MQL (назад / повторный вход) → изменение не сохраняется; стадия остаётся SQL (критерий 2: только последовательная цепочка).
- Пользователь с правом смены стадии (ответственный или его руководитель) меняет Won на другую стадию (например Opportunity) → стадия сохраняется; в истории есть переход Won → выбранная стадия с сотрудником и датой/временем; период на Won закрыт, открыт период на новой стадии.
- Как руководитель ответственного за лид (его линейный/орг-руководитель) меняет Won на другую стадию (пример 3B: Anna, только если Anna — руководитель этого ответственного, а не любой руководитель компании) → стадия сохраняется.
- Сменить стадию lifecycle при неизменном этапе воронки → этап воронки на карточке не меняется.
- Сменить этап воронки (пример из тикета: «Демо» → «КП отправлено») при неизменной стадии lifecycle → стадия lifecycle не меняется автоматически; период текущей стадии lifecycle не закрывается.
- Сменить стадию lifecycle → статус компании, контакт и стадии других лидов той же компании не меняются.
- Автор лида, который не является ответственным и не является руководителем ответственного, пытается сменить стадию → изменение не сохраняется; стадия видна только для просмотра.
- Пользователь, который не является ни ответственным за лид, ни руководителем этого ответственного, открывает карточку → стадия видна только для просмотра, сменить нельзя.
- После разрешённой смены стадии открыть историю на карточке лида → запись содержит предыдущую стадию, новую стадию, сотрудника, инициировавшего переход, дату и время.
- После разрешённой смены стадии → предыдущий период на старой стадии закрыт (дата/время выхода и кто закрыл период); открыт новый период на новой стадии (дата/время входа).
- Если лид уже бывал на стадии (например MQL), затем получил Won, и пользователь с правом смены переводит Won обратно на MQL → создаётся новый период на MQL; прежние периоды сохранены; дата первого достижения MQL не перезаписывается.
- При первом включении функции открыть существующий лид без ранее заданной стадии → текущая стадия Lead; зафиксированы факт и дата инициализации lifecycle.
