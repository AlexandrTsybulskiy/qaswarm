Пользователь Upservice просит **ИИ-сотрудника** в **диалоге** создать контакт типа **Частное лицо** (не представитель компании). Контакт после успешного создания появляется в разделе **«Контакты и чаты»** и в **карточке контакта** так же, как при ручном создании; в том же диалоге ИИ-сотрудник отправляет **подтверждение** и **ссылку** на контакт. Заполнение полей, обязательность, проверки формата, права, ошибки и отказ — **по тем же правилам**, что при **ручном** создании контакта в интерфейсе. Отдельная дедупликация и объединение контактов **не выполняются**.

## Testable

- Пользователь с правом создания контактов пишет ИИ-сотруднику в диалоге однозначный запрос на создание контакта-частного лица с именем, телефоном и ответственным → ИИ-сотрудник **принимает** запрос (не отказывает без причины из критериев) и **инициирует** флоу создания
- Пользователь просит создать контакт через ИИ-сотрудника в диалоге → создаётся контакт только как **Частное лицо**; флоу **Представителя компании** в этой Story **не доступен**
- Запрос «Создай контакта Иван Петров, +375291234567, ответственный — я» с указанными необязательными полями (фамилия, отчество, email, комментарий, дата рождения, метки, должность, адрес, ссылка на профиль) → в карточке контакта заполнены **все указанные** поля; **не указанные** необязательные поля **пустые**
- Запрос без **имени** или без **телефона и email** или без **ответственного** → ИИ-сотрудник **задаёт уточняющие вопросы** по недостающим обязательным полям и **не создаёт** контакт **до** получения ответа
- Запрос «Создай контакты: Анна +375291111111; Борис anna@example.com; Петр +375292222222, petr@example.com» с явным указанием множественного создания → за один запрос создаётся **несколько** контактов-частных лиц (по одному на каждую пару имя–телефон или имя–email)
- Запрос с одной парой имя–контакт без явного множественного создания → создаётся **ровно один** контакт
- Значения полей из запроса (телефон, email, дата и т.д.) → сохраняются **как переданы** и проходят **те же проверки формата**, что при ручном создании контакта в форме
- Пользователь **без** системного права создания контактов просит создать контакт в диалоге с ИИ-сотрудником → ИИ-сотрудник **не создаёт** контакт, **не ищет** связанные значения (метки, ответственного и т.п.) и **не уточняет** поля; сообщает **недостаточно прав**
- Проверка прав выполняется **до** уточняющих вопросов по полям → при отсутствии прав уточняющие вопросы **не задаются**
- Запрос на создание контакта с данными, при которых **ручное** создание в интерфейсе **допускает** второй контакт (без объединения) → ИИ-сотрудник **создаёт** второй контакт; **отдельная** дедупликация/объединение **не выполняется**
- Запрос с **неверным форматом** номера телефона (та же ошибка, что при ручном создании) → контакт **не создаётся**; текст ошибки **возвращается** пользователю **в том же диалоге** через ИИ-сотрудника
- Запрос с телефоном, который при ручном создании даёт ошибку **дубля существующего контакта** → контакт **не создаётся**; текст ошибки **возвращается** в диалоге через ИИ-сотрудника
- Успешное создание контакта по запросу → контакт **виден** в разделе **«Контакты и чаты»** и открывается в **карточке контакта** как при ручном создании
- После успешного создания → ИИ-сотрудник в **том же диалоге** отправляет **подтверждение** результата и **ссылку** на созданный контакт
- Контакт **не создан** из‑за **неоднозначного** значения поля (например, несколько меток с одинаковым названием) → ИИ-сотрудник **уточняет** значение **до** создания
- Связанное значение (**ответственный**, **метка**) **не найдено** → ИИ-сотрудник **уточняет** или **отказывается** от поля (по сценарию ручного создания) **до** создания контакта
- Создание **отклонено** правилами продукта так же, как при ручном создании → ИИ-сотрудник сообщает **причину отказа** в диалоге; контакт **не появляется** в «Контакты и чаты»
