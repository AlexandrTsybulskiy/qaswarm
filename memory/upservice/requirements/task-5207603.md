AI-сотрудник по естественной команде пользователя добавляет или удаляет сотрудников из состава участников сущности (задачи, тикеты, лиды, контакты, записи справочников), если у AI есть права на изменение состава. Успех подтверждается уведомлением пользователю; приватные и ограниченные задачи следуют той же логике доступа, что и ручное добавление через UI. Повторно добавить уже участника или удалить не-участника нельзя; недоступную или ненайденную сущность AI не меняет и сообщает об этом.

## Testable

- Пользователь просит добавить или удалить сотрудников из сущности → AI определяет действие (добавление или удаление) из запроса и применяет его к указанной сущности, не выполняя противоположное действие.
- Пользователь даёт команду по задаче → AI добавляет или удаляет участников задачи при наличии прав.
- Пользователь даёт команду по тикету → AI добавляет или удаляет участников тикета при наличии прав.
- Пользователь даёт команду по лиду → AI добавляет или удаляет участников лида при наличии прав.
- Пользователь даёт команду по контакту → AI добавляет или удаляет участников контакта при наличии прав.
- Пользователь даёт команду по записи справочника → AI добавляет или удаляет участников этой записи при наличии прав.
- У AI-сотрудника нет прав на изменение состава участников сущности → AI не добавляет и не удаляет сотрудников.
- Пользователь просит добавить одного сотрудника в сущность → сотрудник появляется в составе участников.
- Пользователь просит добавить нескольких сотрудников в одной команде → все указанные сотрудники появляются в составе участников.
- Пользователь просит удалить одного сотрудника из сущности → сотрудник исчезает из состава участников.
- Пользователь просит удалить нескольких сотрудников в одной команде → все указанные сотрудники исчезают из состава участников.
- Добавление или удаление выполнено успешно → AI уведомляет пользователя об успешном выполнении.
- Пользователь просит добавить сотрудника в приватную или ограниченную задачу → доступ выдаётся по той же бизнес-логике, что и при ручном добавлении участников в интерфейсе (включая доступ к задаче, вложениям и чату задачи, как в примере с Максимом).
- Пользователь просит добавить сотрудника, который уже является участником сущности → AI не добавляет его повторно.
- Пользователь просит удалить сотрудника, который не является участником сущности → AI не выполняет удаление.
- Сущность не найдена или недоступна AI/пользователю → AI сообщает об этом и не меняет состав участников.
- Пример: «Добавь Екатерину в задачу «Интеграция Telegram»» → Екатерина в списке участников этой задачи и имеет доступ к задаче и её чату.
- Пример: «Удали Алексея из справочника «Поставщики»» → Алексей убран из участников соответствующей записи справочника, ранее выданные права доступа отозваны.

## Gaps

- В снимке задачи нет Figma-URL → `source_design: none`, `figma_urls: none`; UI кнопки «Права доступа» и диалога AI не сверять с макетом.
- Заголовок упоминает кнопку «Права доступа»; АС описывают естественные команды AI, а не клик по кнопке. Связь кнопки UI с AI-командами в тикете не раскрыта.
- В `catalog/api.md` нет ресурса AI-сотрудника и отдельного API «права доступа» / состава участников. Связанные публичные пути: `GET|PATCH /v1/tasks/{task_id}` (поля `members`, `access_type`, `chats`, `file_list`), `GET /v1/tasks/{task_id}/attachments`, `GET /v1/tasks/{task_id}/co-responsibles` (только GET, для meeting/acquaintance), `GET /v1/employees`, `GET|PATCH /v1/directory-records/{record_id}`, `GET|POST /v1/channels/messages`. Эндпоинты выдачи/отзыва доступа AI, лидов и контактов не выдумывать.
- Тикет в памяти — `kind: ticket` на сущности `tasks`; отдельных карточек лидов и контактов в `entities/` нет.
- `entities/directories.md` и `entities/employees.md` — `map` only: поля участников записи справочника, модель прав и идентификация AI-сотрудника (роль, ФИО, отдел) не детализированы.
- П. 6 АС помечен как опциональный (поиск по ФИО и по роли, примеры «Добавь ваню из отдела маркетинга», «Добавь главного бухгалтера») — не включён в обязательные Testable; критерии разрешения неоднозначных ФИО/ролей не заданы.
- Тексты уведомлений об успехе, отказе по правам, «уже участник» / «не участник» и «сущность не найдена» не зафиксированы.
- Пример «из справочника «Поставщики»» смешивает справочник и запись справочника (АС требуют работу с записями); какая именно запись и как AI её выбирает — в тикете не сказано.
- Что именно входит в «ту же бизнес-логику», что UI, кроме доступа к задаче/вложениям/чату для private/restricted, в тикете не перечислено.
