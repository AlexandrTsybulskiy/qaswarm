После регистрации компании личный Web-дашборд нового регистранта должен сразу показывать шесть блоков: пять счётных stat cards и блок «Демо-встреча». Онбординг обязан обеспечить демо-данные в количествах и с атрибутами из таблицы контракта (ответственный по демо-сущностям счётных блоков — регистрант; регистрант — участник демо-встречи); эта история не описывает UI создания сущностей. Счётчики используют текущую логику отбора stat cards без изменений и меняются, если пользователь закрыл демо-тикет или выполнил демо-задачу, по тем же правилам, что для обычных сущностей. Демо-данные не удаляются автоматически; блок «Демо-встреча» не показывается после окончания встречи, сама сущность остаётся в системе.

## Testable

- Сразу после регистрации компании открыть личный дашборд (Web) → отображаются все шесть блоков: «Тикеты в работе», «Закрыть задачи сегодня», «Просроченные задачи», «Просроченные лиды», «Просроченные тикеты», «Демо-встреча».
- Сразу после регистрации, до действий пользователя с демо-данными, прочитать счётные блоки → «Тикеты в работе» = 3, «Закрыть задачи сегодня» = 2, «Просроченные задачи» = 2, «Просроченные лиды» = 1, «Просроченные тикеты» = 1.
- Зарегистрировать компанию 06.08.2026 в 10:00 и открыть личный дашборд в 10:15 → счётчики 3 / 2 / 2 / 1 / 1; блок «Демо-встреча» показывает встречу 06.08.2026, 11:00–12:00.
- После регистрации проверить демо-задачи блока «Закрыть задачи сегодня» → две задачи; срок — дата регистрации; не в финальном статусе; ответственный — регистрант.
- После регистрации проверить демо-задачи блока «Просроченные задачи» → две задачи; срок раньше даты регистрации; не в финальном статусе; ответственный — регистрант.
- После регистрации проверить демо-сущности блоков «Тикеты в работе», «Просроченные лиды», «Просроченные тикеты» → 3 тикета в работе, 1 просроченный лид, 1 просроченный тикет; все попадают в отбор соответствующего stat card; ответственный — регистрант.
- После регистрации открыть блок «Демо-встреча» → одна встреча; дата — дата регистрации; начало = момент регистрации + 1 ч; окончание = момент регистрации + 2 ч (длительность 1 ч); регистрант — участник.
- Сравнить отбор сущностей в пяти счётных блоках с отбором существующих stat cards личного дашборда → логика отбора совпадает, без изменений для демо-данных.
- При «Тикеты в работе» = 3 закрыть один демо-тикет и снова открыть дашборд → «Тикеты в работе» = 2; закрытый тикет остаётся в системе.
- При «Просроченные задачи» = 2 выполнить одну демо-задачу и открыть дашборд → «Просроченные задачи» = 1.
- Изменить состояние демо-сущности (закрыть тикет, выполнить задачу) → счётчик соответствующего блока изменяется по тем же правилам, что для обычных (не демо) сущностей.
- Зарегистрировать компанию 06.08.2026 в 10:00 (встреча 11:00–12:00) и открыть дашборд в 12:30 → блок «Демо-встреча» не показывает эту встречу; встреча доступна в задачах.
- Дождаться окончания демо-встречи и проверить систему → сущность встречи не удалена автоматически; демо-тикеты, задачи и лид также не удаляются автоматически.
- Сразу после регистрации открыть ленту уведомлений (колокольчик) → непрочитанные уведомления об онбординг-событиях отображаются как непрочитанные: подсветка красным и индикатор.
- Сразу после регистрации открыть колокольчик → четыре непрочитанных уведомления о просрочке и одно непрочитанное уведомление о назначении ответственным в задаче.
