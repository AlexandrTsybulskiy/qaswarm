В настройках канала появляется переключатель автоматической приостановки SLA «время на решение тикета» при статусе «В ожидании ответа» (по умолчанию выключен). Если он включён, время ожидания ответа клиента не входит в SLA решения: при переходе в этот статус SLA решения приостанавливается (вручную или автоматически после ответа оператора), при возврате в «В работе» — продолжается с оставшегося времени. Ручная кнопка «Возобновить» сохраняет текущую логику. SLA первого ответа и Client SLA не меняются. Отдельно переименовывается переключатель создания тикетов из обращений канала.

## Testable

- Открыть настройки канала → есть переключатель «Автоматически приостанавливать SLA время на решение тикета в статусе "В ожидании ответа"»
- Открыть настройки канала, где настройка ещё не включалась → переключатель выключен
- Настройка включена; тикет переводят в статус «В ожидании ответа» → SLA оператора / SLA времени на решение автоматически приостанавливается
- Настройка включена; тикет находится в статусе «В ожидании ответа» → это время не учитывается в расчёте SLA «время на решение тикета»
- Настройка включена; тикет возвращают в рабочий статус «В работе» → SLA решения автоматически продолжается с оставшегося времени
- Настройка включена; в ручном режиме нажимают «Возобновить» → поведение кнопки как сейчас (as is), без новой логики этой story
- Настройка выключена; тикет в статусе «В ожидании ответа» → SLA считается по текущей логике: время в этом статусе входит в общее время решения
- Настройка включена; тикет переходит в «В ожидании ответа» автоматически после ответа оператора (если такой автоперевод включён) → SLA решения приостанавливается так же, как при ручном переводе
- Настройка включена; оператор вручную переводит тикет в «В ожидании ответа» → SLA решения приостанавливается
- Происходит запуск или остановка SLA решения → факт фиксируется в системе для последующей аналитики и отчётов
- SLA решения приостановлен (автоматически или вручную) → таймер SLA отображается как «Приостановлен»
- После возобновления SLA решения → таймер продолжает отсчёт с сохранённого значения
- Приостановлено только SLA решения → SLA первого ответа работает по существующей логике без изменений
- Приостановлено SLA решения → Client SLA (ожидание ответа клиента) продолжает работать независимо и задаёт срок ожидания ответа клиента
- Истёк Client SLA при включённой приостановке SLA решения → автоматическое закрытие тикета по Client SLA выполняется без изменений
- Открыть настройки канала → подпись «Создавать тикеты из обращений данного канала» заменена на «Автоматически создавать тикеты из обращений данного канала»
- SLA решения приостанавливается или возобновляется → кнопка «Приостановить»/«Возобновить» и прогресс-бар обновляются в реальном времени
- Пример: SLA решения 3 ч, Client SLA 5 ч, настройка включена; 10:00 создан тикет, 10:20 ответ оператора и перевод в «В ожидании ответа», 14:20 ответ клиента, 15:00 закрытие → активное SLA решения = 1 ч (20 мин + 40 мин); 4 ч ожидания клиента не входят в SLA решения; Client SLA считается отдельно
