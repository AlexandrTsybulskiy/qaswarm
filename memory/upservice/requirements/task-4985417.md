На странице настроек CRM (макет «Настройки воронки») под конечным неуспешным статусом появляется переключатель «Собирать причину провала». При включении открывается список «Причины провала»: каждое значение — одна причина перевода. При переносе лида на стадию с активным переключателем открывается модальное окно выбора причины; без выбранной причины перемещение не завершается. Выбранная причина пишется в лог: ФИО изменившего, причина, дата и время.

## Testable

- Открыть настройки CRM-воронки → заголовок «Настройки воронки»; подзаголовок «Выберите нужную воронку и настройте ее под себя.»; хлебные крошки «CRM» → «Настройки воронки».
- Просмотреть блоки статусов воронки → секции «Начальный статус», «Промежуточные (дополнительные) статусы», «Конечный успешный статус», «Конечный неуспешный статус».
- Посмотреть блок «Конечный неуспешный статус» (пример статуса «Закрыто и нереализовано») → под статусом виден переключатель «Собирать причину провала».
- Включить переключатель «Собирать причину провала» → отображается список «Причины провала» и действие «Добавить причину».
- При включённом переключателе и пустом списке открыть первую строку → плейсхолдер «Кликните для ввода причины».
- Нажать «Добавить причину» → появляется строка для ввода (на макете текст «Новая причина»); у строки есть drag handle, иконки правки и удаления.
- Задать значение в списке «Причины провала» → каждое сохранённое значение — одна причина перевода (пример на макете: «Не устроила цена (сделать первую общую для примера)»).
- Выключить переключатель «Собирать причину провала» → список «Причины провала» не показывается; перенос лида на этот статус не требует причину.
- Перенести лид на стадию, где переключатель включён → открывается модальное окно с заголовком «Причина провала», иконкой закрытия, подписью поля «Причины провала», плейсхолдером «Выберите причины» и кнопкой «Отправить».
- Открыть выпадающий список в модалке → варианты совпадают со значениями из настроек (на макете: «Причина 1», «Причина 2», «Причина 3», «Причина 4»).
- Выбрать причину и нажать «Отправить» → лид переходит на целевой статус.
- После успешного переноса с причиной открыть лог изменений → строка содержит ФИО того, кто изменил, выбранную причину, дату и время (критерий: «ФИО кто измени: Причина + дата и время»).
- При включённом переключателе попытаться завершить перенос без выбранной причины (пустое «Отправить», закрытие модалки, отмена) → лид остаётся на прежнем статусе.

## Gaps

- В `catalog/api.md` нет ресурсов CRM / leads / lead-status / fail-reason. Публичный каталог покрывает files, channels, employees, projects, sprints, tags, tasks, directories. Историю не привязывать к `entities/tasks.md`: тикет Upservice — задача, а история про лиды CRM. Проверка UI-only / API-unknown. `entities: none`.
- Критерий 1 говорит «под КОНЕЧНЫМ статусом»; на макете переключатель только под «Конечный неуспешный статус», не под «Конечный успешный статус» (пример «Оплачено»). Неясно, действует ли сбор причины на успешный финал и на несколько неуспешных статусов.
- Критерий 3: текст модалки «Укажите причину провала»; на открытом файле заголовок «Причина провала», плейсхолдер «Выберите причины» (множественное число при одном выборе не уточнён).
- Экрана лога в Figma нет: где показывается строка, формат даты/времени, пунктуация «ФИО кто измени: Причина».
- Состояние «переключатель выключен — список скрыт» на макете не показано: оба кадра настроек уже с включённым списком.
- Не зафиксировано: перенос при пустом списке причин; обязательность «Отправить» без выбора; поведение закрытия модалки крестиком; подтверждение удаления причины; сохраняется ли порядок drag; можно ли править/удалять причину, уже использованную в логе.
