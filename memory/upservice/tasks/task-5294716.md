## Description

## User Story

Как менеджер продаж,
я хочу видеть автоматический балл скоринга на Kanban и в карточке лида, созданного через регистрацию в Upservice,
чтобы понимать приоритет обработки зарегистрированных лидов.

## Acceptance Criteria

### Scope

1. Скоринг применяется только к лидам с источником «регистрация в Upservice (первый сотрудник воркспейса)» и только в воркспейсе 8. В других воркспейсах блок скоринга не отображается.

### Расчёт балла

2. Итоговый балл лида = сумма баллов всех применимых признаков из таблицы ТЗ (раздел «Скоринг ЗАРЕГИСТРИРОВАННОГО лида»):

- Корпоративная почта: +5
- Фейковая (временная) почта: −30
- Осмысленное название компании: +5
- Корректный номер телефона: 0
- Отсутствует номер телефона: −10
- Очевидно фиктивный номер телефона: −15
- Очевидно фиктивное имя: −10
- На указанном номере нет мессенджеров (tg, wa, max, viber): −20 — только если номер указан и не фейковый
- Планируемое кол-во пользователей: 1 → −10; 2–5 → +10; 6–20 → +25; 21–50 → +30; 51+ → +40
- Запросил демо при регистрации: +40 — только если при регистрации отмечен чекбокс «Нужна онлайн-демонстрация» (задача [5258979](tel:5258979))

3. Штраф за очевидно фиктивное имя/название применяется только к очевидным шаблонам (набор символов, клавиатурные последовательности, ругательства, тестовые обозначения, «ищу работу» и т.п.). Необычные иностранные имена автоматически не штрафуются.
4. При изменении данных , влияющих на признаки скоринга (контакты, планируемое кол-во пользователей и т.д.), балл пересчитывается автоматически.

### Отображение на Kanban

5. На карточке зарегистрированного лида в воркспейсе 8 отображается итоговый балл.

### Отображение в карточке лида

6. В карточке зарегистрированного лида (воркспейс 8) отображаются: итоговый балл и расшифровка — список сработавших признаков с вкладом каждого (+/−N баллов).
7. Признаки, которые не обнаружены или не применимы, в расшифровку не попадают. Неизвестный признак = 0 баллов, без домысливания.

## Examples

### Пример 1. Регистрация с сильными признаками

**Предусловия:** Воркспейс 8. Новый лид создан через регистрацию: корпоративная почта [ ceo@acme.by ](mailto:ceo@acme.by), осмысленное название компании «Acme», телефон корректный с Telegram, планируемое кол-во пользователей 6–20, отмечен чекбокс «Нужна онлайн-демонстрация».

**Действие:** Менеджер открывает Kanban и карточку лида.

**Ожидаемый результат:** Балл = 5 + 5 + 25 + 40 = 75. На Kanban — балл 75. В карточке — расшифровка с четырьмя признаками и их вкладом.

### Пример 2. Фиктивные данные — низкий балл

**Предусловия:** Воркспейс 8. Лид через регистрацию: временная почта, имя  asdasd , телефон отсутствует, 1 планируемый пользователь.

**Действие:** Менеджер открывает карточку лида.

**Ожидаемый результат:** Балл = −[30 − 10 − 10 − 10](tel:30101010) = −60. В расшифровке — четыре сработавших штрафных признака. На Kanban — балл −60.

### Пример 3. Пересчёт при изменении планируемого кол-ва пользователей

**Предусловия:** Воркспейс 8. Лид через регистрацию: корпоративная почта (+5), осмысленная компания (+5), 1 планируемый пользователь (−10). Текущий балл = 0.

**Действие:** При регистрации пользователь уточняет планируемое кол-во до 6–20. Менеджер открывает карточку лида.

**Ожидаемый результат:** Балл пересчитан: 5 + 5 + 25 = 35. В расшифровке признак «Планируемое кол-во пользователей: 6–20 → +25» вместо «1 человек → −10».
