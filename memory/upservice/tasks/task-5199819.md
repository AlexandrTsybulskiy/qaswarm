## Description

## User story

Как новый пользователь Upservice, завершивший регистрацию компании,
я хочу сразу видеть на личном дашборде осмысленные блоки со счётчиками и демо-встречу,
чтобы понять, какие сущности требуют моего внимания в системе.

## Контекст и проблема

После регистрации компании личный дашборд нового пользователя не даёт полезной картины по задачам, тикетам, лидам и встречам.

Онбординг уже создаёт в workspace реальные сущности. Эта Story **не описывает создание сущностей** — только контракт: **что должно отображаться** на личном дашборде нового регистранта и **какой состав и количество демо-данных** онбординг должен обеспечить.

**Новый регистрант** — пользователь, завершивший регистрацию компании.

## Выбранное решение

### Блоки личного дашборда (Web)

1. **Тикеты в работе**
2. **Закрыть задачи сегодня**
3. **Просроченные задачи**
4. **Просроченные лиды**
5. **Просроченные тикеты**
6. **Демо-встреча**

Счётные блоки (1–5) — stat cards с **текущей логикой отбора без изменений**. Счётчики отражают актуальное состояние: если пользователь закрыл демо-тикет или выполнил демо-задачу, значение блока изменяется по тем же правилам, что и для обычных сущностей.

**Демо-встреча** отображается до момента окончания; после — не показывается на дашборде (сущность остаётся в системе).

Демо-данные **не удаляются автоматически**.

### Состав и количество демо-данных

Ответственным по каждой демо-сущности назначается **регистрант**.

| Блок дашборда | Тип | Кол-во | Ключевые атрибуты |
|---|---|---|---|
| Тикеты в работе | Тикет | **3** | Попадают в отбор stat card; ответственный — регистрант |
| Закрыть задачи сегодня | Задача | **2** | Срок — дата регистрации; не в финальном статусе; ответственный — регистрант |
| Просроченные задачи | Задача | **2** | Срок раньше даты регистрации; не в финальном статусе; ответственный — регистрант |
| Просроченные лиды | Лид | **1** | Попадает в отбор stat card; ответственный — регистрант |
| Просроченные тикеты | Тикет | **1** | Попадает в отбор stat card; ответственный — регистрант |
| Демо-встреча | Встреча | **1** | Дата — дата регистрации; начало +1 ч; длительность 1 ч; регистрант — участник |

**Итого:** 4 тикета, 4 задачи, 1 лид, 1 встреча. **Остальные задачи и тд. по текущей логике переносятся**

## Критерии приёмки

1. Сразу после регистрации компании на личном дашборде (Web) отображаются все шесть блоков.
2. Счётные блоки показывают: «Тикеты в работе» = **3**, «Закрыть задачи сегодня» = **2**, «Просроченные задачи» = **2**, «Просроченные лиды» = **1**, «Просроченные тикеты» = **1**. (Для просроченных сущностей берем 10% от каждйо и ставим их просроченными)
3. Логика отбора в счётных блоках совпадает с логикой stat cards личного дашборда без изменений.
4. При изменении пользователем состояния демо-сущности счётчик блока изменяется по тем же правилам, что для обычных сущностей.
5. Блок «Демо-встреча» показывает встречу: дата регистрации, начало +1 ч, окончание +2 ч от момента регистрации.
6. После окончания демо-встречи блок не показывает её; сущность доступна в системе.
7. Ответственным по демо-сущностям в счётных блоках назначен регистрант; регистрант — участник демо-встречи.
8. На каждое событие - непрочитанное уведомление в ленте (Колокольчике), которое должно отображаться как непрочитанное (Подсвечиваться красным с индикатором)
9. Непрочитанные уведомления в колокольчике, номера: 103, 805, **103?!( Просрочка по лиду)**, 23 - на каждое просроченное  и одно на назначение ответстенным в задаче. Т.е. 4 нотификации о просрочке и одна нотификация о назначении ответственным.

## Примеры использования

### Пример 1. Дашборд сразу после регистрации

**Предусловия:** регистрация 06.08.2026 в 10:00. Онбординг создал демо-данные по контракту.

**Действие:** открытие личного дашборда в 10:15.

**Ожидаемый результат:** счётчики 3 / 2 / 2 / 1 / 1; встреча 06.08.2026, 11:00–12:00.

### Пример 2. Закрытие одного демо-тикета

**Предусловия:** «Тикеты в работе» = 3. Пользователь закрывает один из них.

**Действие:** повторное открытие дашборда.

**Ожидаемый результат:** «Тикеты в работе» = 2. Тикет остаётся в системе.

### Пример 3. Выполнение просроченной задачи

**Предусловия:** «Просроченные задачи» = 2. Пользователь выполняет одну.

**Действие:** открытие дашборда.

**Ожидаемый результат:** «Просроченные задачи» = 1.

### Пример 4. Встреча после окончания

**Предусловия:** регистрация 06.08.2026 в 10:00, встреча 11:00–12:00.

**Действие:** открытие дашборда в 12:30.

**Ожидаемый результат:** блок «Демо-встреча» пуст; встреча доступна в задачах.
