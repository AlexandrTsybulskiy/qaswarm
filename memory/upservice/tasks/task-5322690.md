## Description

[Story] — ИИ-сотрудник создаёт тикет по обращению во внешнем чате

## User Story

Как пользователь Upservice,
я хочу, чтобы ИИ-сотрудник — оператор внешнего канала — создавал тикеты по входящим сообщениям, которые по его памяти относятся к определённым обращениям,
чтобы такие обращения из внешних чатов обрабатывались без отдельного правила автоматизации.

## Решение

Вместо правила автоматизации ИИ-сотрудник сам обрабатывает входящее сообщение во внешнем чате по своей памяти.

Когда в чат уже подключённого внешнего канала приходит входящее сообщение, ИИ-сотрудник, который является оператором этого канала, сверяет сообщение со своей памятью. Если в памяти указано создавать тикеты по определённым обращениям и сообщение к ним относится — создаётся тикет. Если сообщение не является таким обращением, ИИ-сотрудник не оператор канала или в памяти нет такой инструкции — тикет не создаётся. Нового экрана нет.

## Acceptance Criteria

1. По входящему сообщению в чате уже подключённого внешнего канала тикет создаёт только ИИ-сотрудник, который является оператором этого канала.
2. Создавать ли тикет, ИИ-сотрудник определяет по своей уже существующей памяти (запись в справочнике и сохранённые правила памяти). Какие обращения считаются определёнными, задаётся текстом памяти.
3. Если в памяти указано создавать тикеты по определённым обращениям и входящее сообщение к ним относится, ИИ-сотрудник-оператор создаёт тикет.
4. Контакт и канал созданного тикета берутся из чата и входящего сообщения.
5. Если входящее сообщение не относится к обращениям, указанным в памяти, тикет не создаётся.
6. Если в памяти ИИ-сотрудника нет инструкции создавать тикеты по таким сообщениям, тикет не создаётся.
7. Если операторами одного канала указаны несколько ИИ-сотрудников, каждый создаёт или не создаёт тикет независимо, по своей памяти.

## Examples

### Example 1

**Предусловия:** К чату контакта подключён внешний канал. ИИ-сотрудник указан оператором этого канала. В его памяти записано: в каналах, где он оператор, создавать тикеты по обращениям о поломке оборудования.

**Действие:** Контакт присылает входящее сообщение «Сломался принтер, не печатает».

**Ожидаемый результат:** ИИ-сотрудник создаёт тикет. Контакт и канал тикета — из этого чата и сообщения.

### Example 2

**Предусловия:** К чату контакта подключён внешний канал. ИИ-сотрудник указан оператором этого канала. В его памяти записано: в каналах, где он оператор, создавать тикеты по обращениям о поломке оборудования.

**Действие:** Контакт присылает входящее сообщение «Спасибо!».

**Ожидаемый результат:** Тикет не создаётся.

### Example 3

**Предусловия:** К чату контакта подключён внешний канал. ИИ-сотрудник не указан оператором этого канала. В его памяти записано: в каналах, где он оператор, создавать тикеты по обращениям о поломке оборудования.

**Действие:** Контакт присылает входящее сообщение «Сломался принтер, не печатает».

**Ожидаемый результат:** Этот ИИ-сотрудник тикет не создаёт.

### Example 4

**Предусловия:** Операторами одного внешнего канала указаны два ИИ-сотрудника. В памяти первого записано создавать тикеты по обращениям о поломке оборудования. В памяти второго такой инструкции нет.

**Действие:** Контакт присылает входящее сообщение «Сломался принтер, не печатает».

**Ожидаемый результат:** Первый ИИ-сотрудник создаёт тикет. Второй тикет не создаёт.

## Не входит в задачу

- Правило автоматизации «Новое сообщение», действие «Обработка ИИ сотрудником» и поле «Что сделать»
- Новый экран настройки реакций или редактор памяти
- Автоответ клиенту
- Подключение новых каналов
- Назначение операторов канала
- Расширение прав ИИ-сотрудника на каналы, где он не оператор
- Классификация обращений сверх того, что следует из текста памяти
- Видимость сообщений внешних каналов для ИИ-сотрудника (задача 5363586)
- Создание тикета ИИ-сотрудником по запросу пользователя (задача 4992787)
