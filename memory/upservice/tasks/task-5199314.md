## Description

## User story

Как пользователь workspace,
я хочу, чтобы настраиваемый ИИ-сотрудник с доступом к Upservice API сам находил нужную информацию — сначала в Upservice, затем при необходимости в интернете,
чтобы получать актуальные и проверяемые ответы без выдуманных фактов и с явным согласия на обращение к интернету.

## Контекст и проблема

Сейчас поиск в интернете для настраиваемых ИИ-сотрудников workspace не описан как продуктовая возможность. У техподдержки используются предзагруженные ссылки, у Ричарда — знания модели без указания источников.

Пользователю нужен понятный порядок: сначала доступные данные Upservice, затем при необходимости интернет — но только с явного разрешения пользователя.

## Критерии приёмки

1. ИИ-сотрудник при ответе сначала использует данные Upservice в рамках своих прав пользователя.
2. Если данных Upservice и базы знаний достаточно для ответа на запрос, поиск в интернете не выполняется и разрешение на интернет не запрашивается.
3. ИИ-сотрудник сам определяет необходимость выхода в интернет, если данных Upservice и базы знаний недостаточно для ответа или в запросе явно указана потребность во внешних или актуальных данных.
4. Перед обращением к интернету ИИ-сотрудник явно запрашивает у пользователя разрешение на поиск в интернете.
5. Поиск в интернете выполняется только после согласия пользователя.
6. Фрагменты ответа из данных Upservice и базы знаний ИИ-сотрудника помечены **«Из Upservice»**.
7. Фрагменты ответа из интернета помечены **«Из интернета»** и содержат кликабельную ссылку на источник.
8. Если после поиска в Upservice и в интернете информации нет, ИИ-сотрудник сообщает, что не нашёл, и не добавляет неподтверждённые факты.
9. Поиск в интернете выполняется только по публичным источникам без авторизации и не включает действия, меняющие данные или состояние во внешних системах.

## Примеры использования

### Пример 1. Ответ из Upservice без интернета

**Предусловия:** У пользователя есть доступ к карточке контакта «ООО Ромашка». В базе знаний ИИ-сотрудника нет отдельной записи по этому контакту.

**Действие:** Пользователь спрашивает: «Какой телефон у контакта ООО Ромашка?»

**Ожидаемый результат:** ИИ-сотрудник отвечает телефоном из Upservice с пометкой **«Из Upservice»**. Поиск в интернете не выполняется, разрешение не запрашивается.

### Пример 2. Запрос разрешения → согласие → поиск в интернете

**Предусловия:** В Upservice и базе знаний нет свежих новостей о компании X.

**Действие:** Пользователь спрашивает: «Найди в интернете актуальные новости о компании X на сегодня». ИИ-сотрудник проверяет Upservice и базу знаний, определяет необходимость интернета и спрашивает разрешение. Пользователь соглашается.

**Ожидаемый результат:** ИИ-сотрудник выполняет поиск в интернете. В ответе фрагменты из интернета помечены **«Из интернета»** со ссылками на источники.

### Пример 3. Запрос разрешения → отказ → без интернета

**Предусловия:** В Upservice и базе знаний нет данных о тарифах конкурента Y.

**Действие:** Пользователь спрашивает: «Какие тарифы сейчас у компании Y?». ИИ-сотрудник проверяет Upservice и базу знаний, определяет необходимость интернета и спрашивает разрешение. Пользователь отказывает.

**Ожидаемый результат:** ИИ-сотрудник не выполняет поиск в интернете. Отвечает на основе данных Upservice и базы знаний, если их достаточно; если недостаточно — сообщает об этом без выдуманных фактов.

### Пример 4. Информация не найдена

**Предусловия:** В Upservice и базе знаний нет данных по запросу. Пользователь согласился на поиск в интернете, но в публичных источниках информации нет.

**Действие:** Пользователь спрашивает: «Когда компания Z планирует IPO?»

**Ожидаемый результат:** ИИ-сотрудник сообщает, что не нашёл информацию. В ответе нет выдуманных дат или фактов.
