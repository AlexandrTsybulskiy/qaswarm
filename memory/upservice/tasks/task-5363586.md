## Description

[Story] - ИИ-сотрудник видит сообщения внешних каналов в чате

## User Story

Как пользователь Upservice,
я хочу, чтобы ИИ-сотрудник с доступом к чату видел сообщения из подключённых внешних каналов и использовал их текст как рабочий контекст,
чтобы я мог опереться на него по входящей переписке, которую сотрудник уже видит в этом чате.

## Решение

Когда входящее сообщение из уже подключённого внешнего канала уже показано сотруднику в чате, ИИ-сотрудник с доступом к этому чату получает то же содержимое и использует его как рабочий контекст. Доступны и история, и только что пришедшие сообщения: источник — то, что сотрудник уже видит в чате, а не триггер «пришло новое». «Понимает» значит, что пользователь может опереться на ИИ-сотрудника по тексту этого сообщения в рамках уже существующих возможностей, без гарантии классификации смысла. Если тот же тред виден в тикете или лиде — это то же сообщение, не отдельный механизм. Нового экрана нет.

## Acceptance Criteria

1. ИИ-сотрудник с доступом к чату получает содержимое входящих сообщений из уже подключённых внешних каналов, которые уже показаны сотруднику в этом чате: и историю переписки, и только что пришедшие сообщения.
2. Источник — сообщения внешнего канала, уже показанные в чате, а не отдельный триггер «пришло новое сообщение».
3. ИИ-сотрудник получает то же представление содержимого, которое уже показано сотруднику в чате, включая вложения в том виде, в каком они видны в чате.
4. Пользователь может опереться на ИИ-сотрудника по тексту такого сообщения: ИИ-сотрудник использует этот текст как рабочий контекст в этом чате в рамках уже существующих возможностей.
5. Если у ИИ-сотрудника нет доступа к чату, сообщения этого чата ему недоступны.
6. Сотрудник видит ту же переписку в существующем чате «Контакты и чаты».

## Examples

### Example 1

**Предусловия:** К чату контакта подключён внешний канал. ИИ-сотрудник имеет доступ к этому чату. Контакт присылает входящее сообщение с текстом «Нужно перенести встречу на пятницу». Сообщение видно сотруднику в чате.

**Действие:** Пользователь в этом чате спрашивает ИИ-сотрудника, о чём написал контакт.

**Ожидаемый результат:** ИИ-сотрудник использует текст этого сообщения как рабочий контекст. Пользователь может опереться на него по тексту, который сотрудник видит в чате.

### Example 2

**Предусловия:** В чате уже есть более ранние входящие сообщения внешнего канала, видимые сотруднику. ИИ-сотрудник имеет доступ к чату. Новое сообщение сейчас не приходит.

**Действие:** Пользователь просит ИИ-сотрудника опереться на одно из уже показанных сообщений канала.

**Ожидаемый результат:** ИИ-сотрудник использует текст этого сообщения из истории чата как рабочий контекст.

### Example 3

**Предусловия:** Сообщение внешнего канала видно сотруднику в чате. У ИИ-сотрудника нет доступа к этому чату.

**Действие:** Пользователь обращается к этому ИИ-сотруднику по тексту сообщения из чата.

**Ожидаемый результат:** Сообщение этому ИИ-сотруднику недоступно.

### Example 4

**Предусловия:** В чат пришло входящее сообщение внешнего канала с вложением. Сотруднику в чате показано определённое представление этого сообщения. ИИ-сотрудник имеет доступ к чату.

**Действие:** Пользователь обращается к ИИ-сотруднику по этому сообщению.

**Ожидаемый результат:** ИИ-сотрудник получает то же представление содержимого, которое уже показано сотруднику в чате.
