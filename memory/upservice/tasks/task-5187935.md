## Description

Как пользователь
я хочу автоматически приостанавливать SLA оператора при переводе тикета в статус «В ожидании ответа»,
чтобы время ожидания ответа от клиента не учитывалось при расчете SLA обработки тикета.

АС

1. В настройках канала добавлен новый переключатель:
**«Автоматически п**риостанавливать SLA время на решение тикета в статусе "В ожидании ответа"»
2. По умолчанию переключатель выключен.
3. Если настройка включена:

- при переводе тикета в статус **«В ожидании ответа»** SLA оператора автоматически приостанавливается;
- время нахождения тикета в данном статусе не учитывается при расчете SLA Время на решения тикета;
- после возврата тикета в рабочий статус ( **«В работе»**) SLA автоматически продолжается с оставшегося времени.
- если в ручном режиме нажали на кнопку Возобновить - логика as is

4. Если переключатель выключен, SLA рассчитывается по текущей логике без изменений (время нахождения тикета в статусе **«В ожидании ответа»** продолжает учитываться в общем времени решения.)
5. Приостановка SLA выполняется независимо от того, каким способом тикет был переведен в статус **«В ожидании ответа»**:

- автоматически (если включен автоматический перевод после ответа оператора);
- вручную оператором.

6. При каждом запуске и остановке SLA информация фиксируется в системе для последующего использования в аналитике и отчетах.
7. Во время приостановки SLA решения as is  как для ручного взаимодействия:

- таймер SLA отображается как **«Приостановлен»**
- после возобновления таймер продолжает отсчет с сохраненного значения.

8. Приостановка SLA решения **не влияет** на работу остальных SLA:

- SLA первого ответа продолжает работать по существующей логике;
- SLA ожидания ответа клиента (Client SLA) продолжает работать независимо и определяет срок ожидания ответа клиента;
- автоматическое закрытие тикета по истечении Client SLA выполняется без изменений.

9. Изменить название тогда "Создавать тикеты из обращений данного канала" на "Автоматически создавать тикеты из обращений данного канала"
10. Кнопка Приостановить\\Возобновить и прогресс-бар в реалтайме меняется

Пример сценария

Настройки:

SLA решения — 3 часа;
Client SLA — 5 часов;
Включена настройка «Приостанавливать SLA решения…».

Сценарий:

10:00 — создан тикет;
10:20 — оператор отвечает клиенту;
10:20 — тикет переводится в статус «В ожидании ответа», SLA решения приостанавливается (израсходовано 20 минут);
14:20 — клиент отвечает;
SLA решения возобновляется, остается 2 часа 40 минут;
15:00 — оператор решает проблему и закрывает тикет.

Результат:

SLA решения = 1 час активной работы (20 мин + 40 мин);
время ожидания клиента (4 часа) не учитывается;
Client SLA рассчитывается отдельно.
